Chapter 2: The Cascade, Specificity, and Inheritance

Topic 2.3: Calculations of Specificity

When writing CSS, you will frequently find that different style rules are trying to change the color or size of the exact same element. We already know that the Cascade is the engine that resolves these conflicts.

Today, we are going to look at the second and most powerful filter of that engine: Specificity.

Priority scorecard analogy

To understand specificity, let's use a real-world analogy.

Imagine you are looking at a map.

  • If someone tells you: "Find a building in Delhi", that is a generic instruction. It is hard to find because there are millions of buildings.
  • If they tell you: "Find a library in Delhi", that is slightly more specific.
  • If they tell you: "Find the natinal Library Delhi Main Branch", that is extremely specific. There is only one!

In CSS, the browser evaluates selectors the exact same way. The more specific your selector is, the higher its priority score.

Generic: p (Targets any paragraph)
Specific: .alert (Targets only paragraphs with class="alert")
Extreme: #promo (Targets one unique element with id="promo")

The 3-column system

To determine which selector is more specific, the browser calculates a mathematical score written in three independent columns: [ID, Class, Element]

  • Element Column: Counts raw HTML tags (e.g., h1, p, div)
  • Class Column: Counts classes (e.g., .accent), attributes, and pseudo-classes
  • ID Column: Counts unique ID selectors (e.g., #featured)

Let's look at how the browser counts these elements inside various selectors: mathematical calculation

Example 1: The Tag Selector

CSS
p {
    color: red;
}

We have exactly one element tag (p). Score: 0, 0, 1

Example 2: The Class Selector

CSS
.accent {
    color: blue;
}

We have exactly one class selector (.accent). Score: 0, 1, 0.

Example 3: Descendant Combinations

CSS
main .accent {
    color: green;
}

We have one tag (main) and one class (.accent). Score: 0, 1, 1.

Example 4: The Pseudo-Class

CSS
a:hover {
    color: orange;
}

We have one tag (a) and one pseudo-class (:hover which behaves exactly like a class). Score: 0, 1, 1.

Example 5: The ID Selector

CSS
#featured-box {
    color: purple;
}

We have exactly one ID selector (#featured-box). Score: 1, 0, 0.

Note: If you write your styles directly in the HTML file using an inline style="..." attribute, it bypasses these selectors entirely and scores a massive 1, 0, 0, 0 in a hidden fourth column, instantly overriding external stylesheets!

Debunking myth

Many CSS tutorials teach specificity as a simple points scale:

  • Element = 1 point
  • Class = 10 points
  • ID = 100 points

This is a myth! Specificity is a coordinate score, not a base-10 number. The columns never carry over to the next column.

CSS
/* Selector A (1 class selector) = [10] */
.accent { color: red; } 

/* Selector B (13 element tags combined) = [11] */
body main div section table tr td ul li em strong { color: blue; }

Using the points myth, you might assume Selector B wins because "11 points beats 10 points."

But in reality, Selector A wins! The browser compares scores column-by-column, starting from left to right. Because Selector A has a 1 in the Class column, it defeats Selector B's 0 in the Class column. The element column can never roll over to override a class selector, no matter how many tags you chain together!

ID Selectors vs. Attribute Selectors

Targeting an element using an ID selector is not the same as targeting it using an ID attribute selector.

CSS
/* Selector A: ID Selector (Specificity = (1, 0, 0)) - WINS! */
#meadow { color: green; }

/* Selector B: ID Attribute Selector (Specificity = (0, 1, 0)) - LOSES */
*[id="meadow"] { color: red; }

Even though both selectors target the exact same HTML element, Selector A wins because attribute selectors are calculated in the Class/Attribute column (0,1,0), whereas true ID selectors are calculated in the ID column (1,0,0).

Common Mistake

Mistake 1

The Overpowered ID Lock:

Avoid using ID selectors (#)for general styling. Because they carry a high specificity score of (1, 0, 0,) they are extremely difficult to override, forcing you to write increasingly complex selectors to make small design adjustments. Stick to class selectors for reusable styles!

Mistake 2

The Inherited Styles Illusion:

Inherited values have no specificity at all. This is why a direct match from the universal selector (*), which has a specificity of (0, 0, 0,) will override inherited text colors.
