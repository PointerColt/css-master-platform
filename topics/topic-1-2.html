Topic 1.2: Workspace Setup & Inspecting

Now that we know how HTML, CSS, and JavaScript work together, it is time to set up our personal digital art studio so we can start creating.

To build websites, we use a code editor. We will use Visual Studio Code (VS Code), which is free and industry-standard. Think of VS Code as your high-tech easel, a clean folder on your computer (let's name it classroom) as your studio workspace, and your HTML and CSS files as your canvas and paint.

Even though we are learning CSS, we must create an index.html file first. Why? Because CSS is paint, and you cannot paint a wall if the physical wall doesn't exist yet! Once we have our HTML structure ready, we create our style.css file and link them together using a <link> tag in the HTML head

But what happens when you write CSS and things do not look the way you planned? Don't worry we see it later first let see the workspace setup.

To make Visual Studio Code (VS Code) completely usable and ready for your HTML and CSS development, here is exactly what you need to do:

1. Download and Install VS Code

First, you download the free code editor from the official Microsoft site VS Code. During the installation process on Windows, a vital trick is to check the boxes that say "Add to path" and "Create a desktop icon".

2. Create Your Workspace Folder

Before typing any code, create a dedicated folder on your computer (we named ours classroom). In VS Code, go to the top menu and select File > Open Folder, then select and open your newly created classroom folder. This structures your VS Code sidebar so you can easily manage your files.

3. Create the HTML Canvas First

Since you cannot paint a wall if the physical wall does not exist, you must create your HTML structure before writing CSS.

* Click the New File icon in the VS Code sidebar and create a file named exactly index.html.

*Instead of writing the boilerplate code by hand, type an exclamation mark (!) and hit Enter. This triggers VS Code's built-in Emmet shortcut, which instantly auto-generates your basic HTML page layout.

4. Create the CSS File

Next, click the New File icon again to create your stylesheet, naming it style.css. (Alternatively, some developers like to organize it inside a dedicated folder named css, creating css/style.css).

5. Link the Two Files Together

Right now, your HTML page has no idea that your stylesheet exists. To bridge them together, you must add a <link> tag inside the <head> container of your index.html file.

Write this exact line: <link rel="stylesheet" href="style.css">

(If you placed your stylesheet inside a CSS folder, update the path to href="css/style.css").


Inspecting

Every browser ships with a built-in tool for inspecting a live webpage: Developer Tools (DevTools). Instead of guessing why a layout looks wrong, DevTools shows you exactly what the browser rendered — the real HTML structure and the real CSS rules currently applied, live.


Open it with F12, or Ctrl+Shift+I on Windows/Linux (Cmd+Option+I on Mac). You can also right-click any element on the page and choose Inspect — this jumps straight to that element in DevTools instead of opening it blank.


The Elements panel has two halves. On the left, the live DOM tree — the actual structure the browser built, which can differ from your raw HTML if JavaScript modified it. On the right, the Styles pane, listing every CSS rule affecting the selected element, in cascade order. If two rules conflict, whichever is applied last in that list is winning — this is the fastest way to debug "why isn't my CSS applying."


Below the Styles pane sits the box model diagram — a small nested rectangle showing the exact pixel values for content, padding, border, and margin on the selected element. This is the single most useful panel for spacing bugs: if something looks shifted or a scrollbar sits in the wrong place, this diagram tells you which of the four layers is responsible, instead of you guessing and editing CSS files blindly.


One more panel worth knowing: Computed. It shows the final, resolved value the browser is actually using after every rule and inheritance is applied — the same value you'd get from JavaScript's getComputedStyle(), which is the exact function this platform's own code-checker uses to grade your exercises.


You can also click any value in the Styles pane and edit it directly in the browser. The page updates instantly — this is how you test a fix before writing it into your actual CSS file. Refreshing the page reverts everything, because DevTools edits are never saved to disk.




Example

Take this CSS rule:

CSS
.card {
    padding: 20px;          /* space inside the border */
    border: 2px solid #E4DFD3;
    margin: 16px;           /* space outside the border */
}

Select an element styled this way in DevTools, and the box model diagram will show four labeled rings: content in the center, then a 20px padding ring, the 2px border, and a 16px margin ring — each with its real measured pixels, not just what's written in the file.
